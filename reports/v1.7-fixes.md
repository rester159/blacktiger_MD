# v1.7: recent feedback fixes

## Changes

- Keep Round 5 rescue dialogue fixed while its rows overlap the half-speed parallax plane.
- Submit chest trap flames before actor sprites: earlier sprite entries win overlaps. Pixel regressions cover both chest constructors.
- Align the ROM header's SRAM range to a 1 KiB boundary for better flash-cart detection.
- Save separate Arcade, Home, and Boss Rush score tables. Existing v1.4–v1.6 high-score records migrate by their stored mode.
- Save both option sets in checksummed alternating SRAM slots.
- Select zombie respawn positions with clear body space and clamp campaign boss motion at solid map walls.
- Constrain horizontal player movement and hold the camera during Round 3 and Round 5 boss fights. Native boss entry now applies the original 10/41 terrain-cell patches to collision and rendering; death resets the closure.
- Reset the Round 5 wave boss vulnerability state after a layer is removed so it can take damage again.
- Update the title version mark to v1.7.

## Arena closure source and implementation

Source audit: fixed routine `0x59b2` calls `0x5dc6` with ROM bank 4 selected. The per-round pointers at bank 4 `0x8d90` describe tile writes to banked scroll RAM. Round 3 writes ten cells, including four new solid floor cells at world Y 1600, X 576–624. Round 5 writes 41 cells, changing 22 empty cells to platforms around X 1104–1152, Y 0–144. These changes are now compiled from verified original-ROM records by `tools/extract_boss_terrain.py`. `test_world.py` checks changed and unchanged collision/map cells; `test_boss_terrain_runtime.py` checks native boss spawning, 204 rendered 8x8 tiles, streaming and death reset. Extraction evidence is retained locally in `.local/v17-boss-closure-source.json`.

## Version comparison (before remaining fixes)

A rebuild of v1.6 commit `65b4e8f` was measured with the same emulator, scene setup, inputs, and 600-refresh windows as the current `d9ea180b` candidate. Level 2 produced 446 presentations (44.6 FPS), worst second 26, against current v1.7's 436 (43.6 FPS), worst second 20. Level 3 was identical: 471 presentations (47.1 FPS), worst second 23. Both versions had zero discarded ticks, VBlank overruns, or cache faults in these samples. This identifies a deterioration in the Level 2 sample and a pre-existing Level 3 pacing shortfall; it does not establish a whole-game performance comparison.

Baseline provenance: original v1.6 gameplay code, current generated game assets (unchanged extractor and Game layout), current title version stamp. The local SGDK enables bank switching; its rebuilt `SEGA SSF` header caused boot failure. Restoring the console field to `SEGA MEGA DRIVE`, matching the actual published v1.6 BIN, allowed the comparison to run. This is a source-build comparison, not measurement of the exact published v1.6 BIN. Rebuild and published hashes plus numeric results are retained in `reports/v16-v17-performance-comparison.json`; raw traces are in `.local/v16-comparison-pacing.json` and `.local/v17-current-cpu.json`. Before the terrain fix, the port used the same world terrain implementation as v1.6; the absent source boss-entry patches therefore predated v1.7.
